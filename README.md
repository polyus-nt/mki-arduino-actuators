# Arduino Actuator

Скетч управляет группой кулеров, получает температуру и эталонную температуру по `AustereSerialMaster`, регулирует скорость кулеров и возвращает их обороты.

## Зависимости

- `AustereSerialMaster` — библиотека связи, подключаемая как `AustereSerialMaster.h`.
- `PinChangeInterrupt` — подсчёт тахо-импульсов всех кулеров.
- `OneWire` — нужен только при использовании функции `read_temperature()` из `KY-001.h`.

## Распиновка

### Линия `AustereSerialMaster`

| Назначение | Пин |
| --- | --- |
| MISO | D3 |
| MOSI | D4 |
| CLK | D5 |
| CS | D6 |
| IRQ | D7 |

### Кулеры

`FansManager` управляет четырьмя кулерами. У каждого свой PWM, тахометр и активное-низким уровнем реле питания.

| Кулер / `idx` | PWM | Tach | Relay |
| --- | --- | --- | --- |
| 1 / `0` | D9 | D10 | D8 |
| 2 / `1` | D11 | D12 | A0 |
| 3 / `2` | D2 | D13 | A1 |
| 4 / `3` | A3 | A4 | A2 |

Тахо-входы используют `INPUT_PULLUP` и библиотеку `PinChangeInterrupt`. Расчёт предполагает два импульса на оборот.

> Важно: LED сейчас также назначен на `A3`, что конфликтует с PWM четвёртого кулера. Оставьте на `A3` только одно устройство. Кроме того, на Arduino Uno `A3` не поддерживает аппаратный PWM: `analogWrite(A3, ...)` работает только как включение/выключение.

## `FansManager`

```cpp
FansManager fans;

fans.setup();
fans.set_speed(100);       // Одинаковая скорость 0..255 для всех кулеров.
uint16_t rpm = fans.get_rpm(0);
uint8_t count = fans.fans_count; // 4
```

- `setup()` настраивает реле, PWM, тахо-входы и обработчики прерываний.
- `set_speed(speed)` устанавливает один PWM-уровень всем кулерам. При `0` реле отключают питание.
- `set_speed(idx, speed)` устанавливает PWM-уровень одному кулеру; используется диагностикой для поочерёдной проверки.
- `get_rpm(idx)` возвращает последнее измеренное RPM кулера `idx`; недопустимый индекс возвращает `0`.
- RPM обновляются не чаще одного раза в секунду. Скетч также раз в секунду выводит RPM всех кулеров в Serial Monitor (`9600 бод`).

## Проверка кулеров

В `arduino-actuator.ino` установите `DEBUG` в `true`. В этом режиме `loop()` не обрабатывает основной протокол: все кулеры сразу включаются с PWM из `FAN_TEST_PWM`, а их RPM выводятся в Serial Monitor раз в 5 секунд. Интервал задаётся константой `FAN_TEST_REPORT_INTERVAL_MS`. Для возврата к полезной работе установите `DEBUG` обратно в `false`.

## Управление по температуре

`updateFanSpeed()` сравнивает текущую температуру `temperature` с эталоном `etalon_temperature`.

- При `temperature - etalon_temperature <= 1 °C` кулеры выключаются.
- Выше порога скорость равна `difference * 51`, но ограничена диапазоном `0..150`.

## Протокол байтов

| Код | Значение | Ответ / последующие байты |
| --- | --- | --- |
| `1` | `POLLING_CODE` | 8 байтов RPM (по 2 на каждый из 4 кулеров), затем `3` |
| `2` | `ACTUATOR_CODE` | Включение кулеров, ответ `3` |
| `3` | `OK_CODE` | Подтверждение или конец последовательности RPM |
| `6` | `TEMPERATURE_WHOLE_CODE` | Далее: signed целый байт температуры, затем код `7`, затем дробный байт |
| `7` | `TEMPERATURE_FLOAT_CODE` | Маркер дробной части температурного пакета |
| `8` | `ETALON_CODE` | Далее: один signed целый байт эталонной температуры |

### Температура

Полный температурный пакет имеет вид:

```text
6, whole, 7, fraction
```

`whole` интерпретируется как `int8_t`. `fraction` нормирован: `0..255` соответствует `0..99` сотым градуса. После получения дробного байта скетч обновляет `temperature`, отправляет `OK_CODE` и пересчитывает скорость кулеров.

### Эталон

```text
8, whole
```

Эталон хранится только как целое signed число.

### RPM

Каждое значение RPM ограничивается диапазоном `0..4500` и сжимается в два байта:

```text
normalized = round(rpm * 65535 / 4500)
high = normalized >> 8
low  = normalized & 0xFF
```

При `POLLING_CODE` порядок ответа:

```text
rpm1_high, rpm1_low,
rpm2_high, rpm2_low,
rpm3_high, rpm3_low,
rpm4_high, rpm4_low,
OK_CODE
```

Приёмная плата должна принять восемь байтов RPM до финального `OK_CODE`. В текущем скетче байт со значением `3` внутри RPM заменяется на `255`, поскольку `3` является управляющим кодом конца пакета на второй плате. Такая замена делает соответствующее значение RPM неточным.

Для восстановления без учёта этой специальной замены:

```cpp
uint16_t normalized = (uint16_t(high) << 8) | low;
uint16_t rpm = ((uint32_t)normalized * 4500 + 32767) / 65535;
```

## Дополнительные заголовки

- `KY-001.h`: `read_temperature(pin)` читает DS18B20 на указанном пине; при отсутствии датчика возвращает `NAN`.
- `KY-025.h`: `setup_gerkon(pin)` настраивает вход, `read_gerkon(pin)` сохраняет старую аналоговую логику: значение АЦП выше `10` возвращает `0`, иначе `1`.

Эти заголовки сейчас не подключены к основному скетчу. При необходимости подключите их и назначьте пины в `arduino-actuator.ino`.
