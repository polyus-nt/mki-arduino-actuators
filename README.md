# Arduino Actuator

Актуальная прошивка: [arduino-actuator.ino](arduino-actuator.ino).
В проекте один скетч: старый PID, температурное управление, EEPROM и legacy удалены.
Arduino выполняет только аппаратные команды для шести вентиляторов.

## Arduino IDE

1. Откройте `arduino-actuator.ino` из папки `arduino-actuator`.
2. Выберите **Arduino Uno**, установите **PinChangeInterrupt 1.2.9** через менеджер библиотек.
3. В [BoardConfig.h](BoardConfig.h) выставьте `API_ACTUATOR_BOARD`: **1** — первая
   Arduino (четыре вентилятора), **2** — вторая (два вентилятора).
4. Нажмите «Проверить», выберите COM-порт именно этой Arduino и загрузите скетч.
   Для следующей платы измените профиль и повторите проверку/загрузку.

По умолчанию выбран профиль 1. Оба профиля имеют согласованную распиновку.

| Плата / шлюз | Общий индекс API | Локальный индекс Arduino | PWM | Тахометр | Реле |
|---|---|---|---|---|---|
| 1 / 14 | 0 | 0 | D10 | D12 | A0 |
| 1 / 14 | 1 | 1 | D11 | D13 | A1 |
| 1 / 14 | 2 | 2 | D6 | A4 | A2 |
| 1 / 14 | 3 | 3 | D9 | D8 | A3 |
| 2 / 17 | 4 | 0 | D10 | D12 | A0 |
| 2 / 17 | 5 | 1 | D11 | D13 | A1 |

Вся распиновка и количество импульсов на оборот находятся только в
`BoardConfig.h`: транспорт задаётся полной группой из пяти `API_LINK_*`.
Частичная транспортная карта останавливает сборку с ошибкой.
PWM-пины должны поддерживать analogWrite, таховходы — PinChangeInterrupt.
Пересечения между PWM, тахо, реле и транспортом запрещены; некорректная карта
отклоняется до доступа к GPIO. Неправильная длина массива — ошибка сборки.
Транспорт по умолчанию: MISO=D2, MOSI=D3, CLK=D4, CS=D5, IRQ=D7.
`API_PULSES_PER_REV=2` — предполагаемые импульсы на оборот; проверьте по модели
вентилятора. RPM обновляется примерно раз в секунду; тишина даёт RPM=0.
Тахометр D13 требует проверки на реальной UNO/клоне с установленным светодиодом.

## Поведение

PWM 0..255; чтение и подтверждение установки возвращают фактически применённый PWM.
PWM=0 выставляет реле HIGH (питание выключено), ненулевой PWM — LOW (включено),
затем применяется analogWrite. При загрузке реле заранее устанавливаются HIGH
до перевода в OUTPUT, PWM=0. get_pwm хранит применённое значение, а не измеряет напряжение.
RPM передаётся как u32, без старой нормализации.
mode=1 меняет PWM выбранного вентилятора сразу и каждые 30 секунд;
mode=2 случайно заменяет только поступающие ему команды установки.
Прошивка обеспечивает один сценарий **на своей плате**. Хаб координирует две
Arduino: выключает предыдущий сценарий с подтверждением до включения нового,
чтобы во всей системе был затронут только один вентилятор.
При потере связи, выключении или смене режима последний PWM сохраняется.
После включения питания PWM=0, mode=0. Замки и пылесос обслуживает восьмилампочница.

Компьютер обращается к виртуальному node14 с общим idx0..5. Хаб преобразует
4/5 в node17/локальный idx0/1 и восстанавливает общий индекс в ответе компьютеру.
Arduino принимает только собственный адрес и локальные индексы: node14/0..3
или node17/0..1. Недопустимый idx даёт INVALID_INDEX без изменения GPIO.

| Команда | Код | Данные запроса | Данные успешного ответа |
|---|---|---|---|
| get_pwm(idx) | 0x30 | 8 нулей | PWM, 7 нулей |
| get_rpm(idx) | 0x31 | 8 нулей | RPM u32 big-endian, 4 нуля |
| set_pwm(idx,pwm) | 0x32 | PWM, 7 нулей | Применённый PWM, 7 нулей |
| get_mode() | 0x40 | idx=0xFF, 8 нулей | mode, локальный idx, 6 нулей |
| set_mode(mode,idx) | 0x41 | mode, 7 нулей | mode, локальный idx, 6 нулей |

Кадр Hardware API v2 остаётся 28-байтовым, с CRC и tx/session. При mode=0
idx ответа равен 0xFF. mode1 продолжает работать без связи; случайный PWM0..255
может выключить реле. Повтор того же режима не перезапускает таймер.
get_mode/set_mode — только Admin API, не MCP tools; Arduino не аутентифицирует кадры.

## Структура и проверки

- `src/ActuatorApi.h` — обработчики команд и сценарии.
- `src/BoardIO.h` — GPIO, тахометры, проверка карты.
- `src/common/HardwareProtocol.h` — бинарный кадр 28 байтов с CRC.
- `src/austere/` — локальная AustereSerialMaster с лицензией upstream.
- `src/main.cpp` — только адаптер PlatformIO; Arduino IDE собирает корневой .ino.

```sh
pio run -e uno -e uno_second
pio run -e uno_compile_check
```

`uno` и `uno_second` — реальные профили первой и второй Arduino.
`uno_compile_check` проверяет код с намеренно конфликтующей картой.
Её карта находится в `test/compile_only_board.h`; числовые пины не задаются
в `platformio.ini`, подключается только файл конфигурации.
Её нельзя прошивать на стенд.
Нативные проверки настоящего BoardIO (нужен компилятор C++11):

```sh
g++ -std=c++11 -Wall -Wextra -Werror test/hardware_api_test.cpp -o api-test
./api-test
g++ -std=c++11 -Wall -Wextra -Werror -Itest/stubs test/board_io_test.cpp -o board1-test
./board1-test
g++ -std=c++11 -Wall -Wextra -Werror -Itest/stubs -DAPI_ACTUATOR_BOARD=2 test/board_io_test.cpp -o board2-test
./board2-test
```

Проверяются безопасный порядок GPIO, полярность реле, RPM, локальные индексы,
адреса и сценарии ошибок. Тесты не заменяют проверку на реальном стенде.
Старый код восстанавливается из истории Git, отдельной legacy-прошивки нет.
